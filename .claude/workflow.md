# チーム開発ワークフロー

---

## 1. ブランチ運用

```
master            # 常にデモ可能な状態を保つ
 └ feat/P1-6-urgency-calculator
 └ feat/P2-1-snippet-command
 └ fix/P1-4-elapsed-badge-timezone
```

- **ブランチ名には必ず要件IDを含める**：`feat/{要件ID}-{英語の短い説明}`
- 1ブランチ＝1要件。複数要件をまとめない
- `master` に直接 push しない

## 2. コミットメッセージ

```
{type}: {日本語で要約}

feat: 緊急度算出サービスを追加
fix: 経過時間バッジが done でも表示される不具合を修正
refactor: メッセージキャッシュを Pinia ストアへ移行
docs: CLAUDE.md に定型文の仕様を追記
```

type：`feat` / `fix` / `refactor` / `docs` / `chore`

## 3. Pull Request

- タイトルに要件IDを含める
- 本文に**該当要件の受入条件をチェックリストで貼り、自分で確認してからレビュー依頼**する
- レビュー観点は §6 のチェックリストを使う

## 4. コンフリクトしやすい共有ファイル ★注意

以下は複数人が同時に触ると必ず衝突する。**変更する場合は事前にチームへ周知し、単独の小さな PR にすること。**

| ファイル | 理由 |
| --- | --- |
| `shared/constants.js` | 全機能が参照する |
| `server/db/schema.sql` | 全機能が参照する |
| `server/db/seed.js` | 各自がデモデータを足したくなる |
| `server/sockets/index.js` | ハンドラ登録が集中する |
| `client/src/router/index.js` | ルート追加が集中する |

**対策**：スキーマと定数は Day1 午前に確定させ、以降は原則変更しない。ハンドラは `sockets/handlers/` に機能別ファイルで分割し、`index.js` への追記は1行に留める。

## 6. 完了の定義（Definition of Done）

要件を「完了」と宣言する前に、以下をすべて満たすこと。

- [ ] `requirements.md` の該当要件の**受入条件をすべて満たしている**
- [ ] 列挙値を `shared/constants.js` から import している（文字列リテラル直書きがない）
- [ ] サーバ側で認可チェック（`room_members` の確認）を行っている
- [ ] SQL がプレースホルダになっている
- [ ] `v-html` を使っていない
- [ ] Socket イベントのハンドラが `useSocket.js` に集約されている
- [ ] `npm run lint` が通る
- [ ] **2ブラウザ（人事・学生）で実際に動作確認した**
- [ ] リロードしても壊れない

## 8. デモシナリオ（この流れが動くことを最優先）

1. 受信箱を開く → 「要返信 7件・緊急 2件」のサマリーと、赤バッジの並んだ一覧を見せる
2. **別ブラウザの学生が「明日の面接、体調不良で欠席します」と送信**
3. 人事画面で、リロードなしに該当学生が最上位へ移動し、`欠席・遅刻` タグと `緊急` が自動付与される
4. 人事が `/日程案内` を入力 → 学生名・面接日時が自動補完された定型文が展開される
5. 送信 → 対応ステータスが自動で `返信待ち` に遷移し、一覧の順位が下がる
6. 別の人事アカウントで同じ学生を開き、共有メモから経緯を把握できることを見せる

**デモ文言は `tag_rules` の辞書で確実にヒットする語を含めること。**

## 9. リスクと対応

| # | リスク | 対応策 |
| --- | --- | --- |
| R-1 | 外部AI API（P3-1）の障害・遅延 | 3秒タイムアウト＋ルールベースへの自動フォールバック。APIキー未設定でも全機能が動作すること |
| R-2 | Socket 再接続時のメッセージ欠落 | 再接続時に各ルームの最新メッセージIDを送り、差分を REST で再取得 |
| R-3 | 楽観的UIによるメッセージ重複 | `client_msg_id` を UNIQUE 扱いにし、サーバで重複を無視して既存を返す |
| R-4 | P1 が Day2 中に終わらない | P2・P3 を全て切り捨てて P1 を優先。P3 は「1つだけ」を厳守 |
| R-5 | 緊急度の判定精度が低くデモで外す | 辞書をシードデータで事前検証。デモ文言に確実にヒットする語を含める |
| R-6 | SQLite の書き込みロック競合 | WAL モード＋書き込みトランザクションを短く保つ |
