## P0｜基盤要件（Day1）

### A-1. メッセージの永続化
すべてのメッセージを SQLite に保存し、入室時に過去ログを取得する。詳細は `database.md`。

**受入条件**
- サーバを再起動してもメッセージが消えない
- ルームを開いた直後に過去のメッセージがすべて表示される
- 別ブラウザで同じアカウントにログインしても同じ履歴が見える

### A-2. 独立したバックエンド
Vite dev サーバ依存を解消し、Express + Socket.IO の独立プロセスへ分離する。
開発時は Vite の `server.proxy` で `/api` と `/socket.io` を `localhost:3000` へ転送。

**受入条件**
- `npm run build` した静的ファイルを Express から配信してもチャットが動作する
- Vite を停止しても API サーバ単体で REST が応答する

### A-3. 認証・セッション
ID＋パスワード認証（bcrypt cost 10）、JWT を httpOnly Cookie で発行。
**ルーターガードを認証状態ベースに置換する**（`frontend.md` 参照）。

**受入条件**
- ログイン後に F5 でリロードしてもログイン画面に戻されない
- 未ログインで `/inbox` に直接アクセスするとログイン画面へリダイレクトされる
- DB にパスワードが平文で保存されていない

### A-4. ルーム概念
全体ブロードキャストからルーム単位の配信（`socket.join`）へ変更する。
接続時に自分の所属する全ルームへ一括 join する。

**受入条件**
- 学生Aへのメッセージが学生Bの画面に表示されない
- 受信箱を開いたままでも、どのルームの新着でも一覧が更新される

### A-5. 状態管理（Pinia）
`provide/inject` のバケツリレーを廃止し、Pinia ストアへ集約する。詳細は `frontend.md`。

**受入条件**
- 任意のコンポーネントから props を経由せず未読数を参照できる
- ルーム切替時に既読済みメッセージが再フェッチされない

### B-1. トークリスト画面
→ **P1-1（受信箱）に統合。** 本プロダクトではトークリストが受信箱そのもの。別画面として実装しない。

### B-2. トーク画面 UI
吹き出し・アイコン・時刻・日付セパレータ・古い→新しい順・無限スクロール。詳細は `frontend.md`。

**受入条件**
- 自分と相手の発言が左右で明確に区別できる
- 100件以上の履歴があるルームで、上スクロールにより過去ログが継ぎ足し表示される
- 日付をまたぐ会話にセパレータが表示される

### B-3. メッセージ機能
既読管理・送信状態（送信中→送信済→既読）・失敗時の再送・24h以内の送信取消。

**受入条件**
- オフライン状態で送信すると失敗表示と再送ボタンが出る
- 再送してもメッセージが二重に保存されない
- 相手がルームを開くと自分の吹き出しに「既読」が1秒以内に付く

### B-5. プロフィール
表示名・ステータスメッセージの編集のみ。アイコンは `avatar_color` の選択。

**スコープ外**：ユーザーID検索、友だち追加・削除・ブロック、グループ作成・招待・退会

### P1-1. 学生一覧（受信箱）画面 ★主画面
1行＝1学生。表示項目とレイアウトは `frontend.md` を参照。
**ログイン直後の着地は S-07 ホーム（下記）が担う。** この要件は「対応の主画面」としての受信箱を指す。

**受入条件**
- 別ブラウザから学生がメッセージを送ると、リロードせず該当行が最上位付近に移動し未読バッジが増える

### S-07. ホーム（学生一覧ボード）
ログイン後の着地点。**ステータスごとの列に学生カードを積んだボードで俯瞰する画面**。
レイアウトは `frontend.md` §5-2。返信はここでは行わず、カードクリックで `/inbox/:roomId`（S-04）へ渡す。
サイドバー（ナビレール）に「ホーム」項目を追加する。

**受入条件**
- 人事でログインすると `/home` が表示される（学生は従来どおり `/chat`）
- `/home` でリロードしてもログイン画面に戻されない
- 既定では**対応ステータス**で縦割りされ、列は `要返信 → 対応中 → 返信待ち → 完了 → 保留` の順に並ぶ
- 切替ボタンで縦割りの軸を**対応／選考／緊急度**に変えられ、カードのチップもそれに追随する
- 列の中は緊急度の高い順に並ぶ（並び替え UI は無い）
- カードには アイコン・氏名・残り2つのステータス・経過時間・新着の有無 が出る
- 新着は件数ではなく点で示される
- カードをクリックすると該当学生のトークが `/inbox/:roomId` で開く
- サイドバーからホームと受信箱を相互に行き来できる
- 画面右下に AI 起動ボタン（円形）があり、右カラムに AI 現況サマリーの枠がある（中身は P3-1a）

### S-08. 全学生（担当人事別ボード）
受信箱（P1-1）とホーム（S-07）は担当制で**自分の担当学生しか表示しない**ため、
担当外・未配属を含む全学生を俯瞰する画面を別に持つ。**対応漏れの拾い上げが目的。**
レイアウトは `frontend.md` §5-3（ホームと同じボードを流用し、縦割りを担当人事に固定する）。
サイドバー（ナビレール）に「全学生」項目を**受信箱の下**に追加する。

**受入条件**
- `/students` に自分の担当以外の学生も表示される
- 列は担当人事ごとに分かれ、**未配属が一番左**にある
- 担当が0名の人事の列も出る
- 縦割りの軸を切り替える UI は無い（担当人事に固定）
- 未対応サマリーバー（P1-8）が**全学生の件数**で出る（自分の担当だけの件数ではない）
- AI 現況サマリーは無い
- カードをクリックすると担当外の学生でもトークが `/inbox/:roomId` で開く
- フィルタ・検索・並び順は受信箱・ホームと同じ条件を共有する

### P1-2. 対応ステータス
`要返信 / 対応中 / 返信待ち / 完了 / 保留`。**一覧から1クリックで変更可能**、色で区別。
手動変更時は `type='system'` のシステムメッセージを記録する。

**受入条件**
- 一覧を離れずに2クリック以内でステータスを変更できる
- 他の人事の画面にも即座に反映される

### P1-3. 選考ステータス（ラベル）
`エントリー / 書類 / 適性検査 / 一次〜五次面接 / 内定 / 辞退`。**面接は5回**（実データ準拠）。

**受入条件**：一覧行に現在の選考段階が常に表示されている

### P1-4. 経過時間バッジ（SLAアラート）
学生の最終メッセージからの経過時間。**24h超で赤、12h超で黄**。判定は `business-logic.md`。
課題 C-1「合否連絡が1日遅れた」への直接の回答。

**受入条件**
- 24時間以上返信していない学生の行が赤で強調される
- 返信すると（`waiting_student` へ遷移し）バッジが消える

### P1-5. 用件タグ（自動判定）
`欠席・遅刻 / 日程調整 / 質問 / 適性検査 / 合否待ち / その他` をサーバ側で自動付与。
**学生にはタグを選択させない**（入力負担と誤選択の責任所在を回避）。辞書は `business-logic.md`。

**受入条件**
- 「明日の面接、体調不良で欠席させてください」に `欠席・遅刻` が付与される
- 辞書に該当しないメッセージは `その他` になる

### P1-6. 緊急度の自動判定
用件タグ＋経過時間から `緊急 / 通常 / 低` を算出。**欠席・遅刻は無条件で緊急**。
判定表と再計算タイミングは `business-logic.md`。

**受入条件**：欠席連絡が届いた瞬間に、その学生が一覧の最上位に移動する

### P1-7. フィルタ＆ソート
対応ステータス／選考ステータス／用件タグ／緊急度／担当者で絞り込み。
デフォルトソートは `最終メッセージ順（新しい順）`（`緊急度 → 経過時間（長い順）` は「緊急度順」として選択可能）。「自分の担当のみ」トグルを用意。

**受入条件**
- 「要返信 かつ 緊急」で絞ると該当学生のみ表示される
- 条件をクリアすると全件に戻る

### P1-8. 未対応サマリーバー
画面上部に「要返信 7件・緊急 2件・24h超 1件」を常時表示。各項目クリックでフィルタ適用。

**受入条件**：学生からメッセージが届くと、リロードせず件数が増える

### P2-10. 会社情報の設定と学生への表示 ★学生側の体験向上
人事が設定画面で会社情報（会社名／紹介文／採用サイトURL）を登録すると、
**学生のトーク画面の右に常設される会社情報パネル**に反映される。
選考中の学生が返信を待つ間に自社を知る接点を持たせるのが目的。

配置は**タブ（別画面）ではなく余白の常設パネル**にする。学生は能動的に情報を探しに来ないため、
隠れたタブでは導線が成立しないという判断（レイアウトは `frontend.md` §7-2）。

**受入条件**
- 人事が設定 → 会社情報 で会社名・紹介文・採用サイトURLを保存できる
- 学生が `/chat` を開くと右側に会社情報パネルが出て、保存した内容が表示される
- 採用サイトのリンクは新しいタブで開く
- **学生は会社情報を編集できない**（設定画面に会社情報の項目自体が出ない）
- 会社情報が未設定でもトーク画面が壊れない（パネルに「まだ公開されていません」と出るだけ）
- `http://` `https://` 以外のURLは保存時に弾かれる

**スコープ外**：会社情報の変更をリアルタイム配信すること（更新頻度が低いため）、
定型文の変数（`{会社名}` 等）への展開、ロゴ画像のアップロード

### S-09. 学生マイページ（選考状況）
**学生のログイン後の着地点**（`/mypage`）。上に会社情報（P2-10 のパネルを横長で流用）、
下に選考フローの進捗を置く。返信はここでは行わず、チャットはナビレールから `/chat` へ。
レイアウトは `frontend.md` §7-3。

**受入条件**
- 学生でログインすると `/mypage` が表示される（人事は従来どおり `/home`）
- `/mypage` でリロードしてもログイン画面に戻されない
- 人事・admin が `/mypage` を開くと自分のホームへ戻される
- ナビレールから マイページ ⇄ チャット を相互に行き来できる

### P2-11. 選考フローの設定と学生への可視化
人事が設定画面で選考フローを設定すると、学生のマイページに**丸とつなぎ線の図**として並び、
学生は自分がいまどの段階にいるかを一目で把握できる。ステップをクリックすると
その選考の内容・ポイント、完了済みなら企業からのフィードバックが読める。

**ステップの識別子は `shared/constants.js` の `SELECTION_STATUS` が正。**
会社が設定するのは「どれを使うか」「学生向けの表示名」「説明・ポイント」だけで、
新しいステップ種別の追加はできない。選考ステータスは受信箱・ホーム・全学生・フィルタ・
AI要約・定型文変数が同じ値を共有しているため、ここを可変にすると全部が巻き添えになる。

**受入条件**
- 設定 → 選考フロー で、ステップの有効・無効、表示名、説明、ポイントを保存できる
- 有効にしたステップだけが学生のマイページに設定した順で並ぶ
- 学生の現在地が「進行中」として示され、そこまでのつなぎ線が塗られる
- ステップをクリックすると内容とポイントが読める
- **企業からのフィードバックは、その学生が通過済みのステップのぶんだけ本人に見える**
  （進行中・未到達のFBはサーバのレスポンスに含めない）
- 人事は受信箱のプロフィールパネルからステップごとにFBを書ける
- 有効なステップが0件になる設定は保存できない
- 辞退した学生にはフロー図を出さず、終端の文言に切り替える
- 学生は選考フローを編集できない（設定画面に項目自体が出ない）

**スコープ外**：新しいステップ種別の追加・削除、FBのリアルタイム配信、
装飾つきテキスト（太字・箇条書き）、ステップごとの添付ファイル

### P3-1. AI 緊急度判定・要約
P1-6 のルールベースを Gemini API に置換。「今日の要対応3件」を自動要約。**デモ映え最大**。
**フォールバック要件は必須**（`business-logic.md` §7）。

**受入条件**：API を意図的に停止しても、アプリが停止せずルールベース判定で動作を継続する

#### P3-1a. AI 現況サマリー／TODO カード（ホーム右カラム）
S-07 ホームの右カラムに、**いま人事が置かれている状況の要約**と**上位のやることリスト**を表示する。
UI の枠・状態遷移・起動ボタンは S-07 で先に用意し、この要件では中身を接続する。

- **生成タイミング**
  - ログイン成功時にサーバ側で自動生成を開始し、ホーム表示時には出来ている状態を狙う
  - 生成後は `generatedAt` つきでキャッシュし、**同じ内容を再生成しない**
  - 右下の円形 AI ボタン、またはカードの「更新」で**手動再生成**できる
- **表示内容**
  - `situation`：現状の1〜2文の要約（例「要返信7件のうち2件が24時間を超えています」）
  - `todos`：対応すべき学生の上位3件。各件に `roomId` / `studentName` / `action` / `reason`
  - TODO の行クリックで該当ルームへ遷移する
- **状態**：`idle`（未生成）／`loading`（生成中）／`ready`／`error`／`unavailable`（APIキー未設定）

**受入条件**
- ログイン後にホームを開くと、AI サマリーが生成済みで表示されている
- AI ボタンを押すと再生成され、`generatedAt` が更新される
- `GEMINI_API_KEY` を外すとカードが `unavailable` 表示になるだけで、**ホームの一覧は通常どおり動作する**
- TODO をクリックすると該当学生のトークが開く
